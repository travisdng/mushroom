# Mushroom v0.4.0

**Released:** 2026-09-16 · **Milestone:** 04 — AI provider and settings

> Mushroom can now be pointed at an AI service — a LiteLLM gateway, OpenAI
> directly, or anything else that speaks the same API. It does not yet ask it
> anything; that is the next release. But the connection works, and your key is
> kept where keys belong.

## What's new

- **`Tools → Settings`.** A proper dialog in the period style: etched group
  boxes, right-aligned labels, OK / Cancel / Apply, Escape to cancel, and full
  keyboard navigation.
- **Two providers out of the box.** LiteLLM (a local proxy, usually
  `http://localhost:4000`) and OpenAI directly. Anything else that speaks the
  OpenAI chat-completions API works by typing its URL.
- **Your API key goes in Windows Credential Manager**, one entry per provider.
  It is never written to `config.json`, never written to a log, and never
  returned across the boundary to the interface — the dialog is told only
  whether a key exists.
- **`Test Connection`** makes one deliberately tiny request and tells you what
  happened: the endpoint, the model the service says it used, and how long it
  took — or a specific reason it failed.
- **A model drop-down** filled from the service's own `/models`, with a
  `Refresh` button. Services that do not offer one fall back to a text field
  rather than an error.
- **The notes folder is editable from Settings**, with a native folder picker
  and a plain warning that changing it re-scans and re-indexes.
- **Advanced settings**: request timeout, context budget, temperature, and a
  prompt-logging switch that is off by default, because prompts contain your
  notes.

## What doesn't work yet

- **Nothing asks the AI anything.** There is no AI panel and no question box;
  that is milestone 05. This release is the plumbing and the settings for it.
- `Tools → Diagnostics` is still greyed out.
- `File → Open`, `Import`, `Export`, and `Save As` still are not wired to a
  file picker.
- The installer is unsigned.

## Where your key lives

This is the part worth being specific about.

- It is stored in **Windows Credential Manager** under `Mushroom`, keyed per
  provider, so switching between LiteLLM and OpenAI does not destroy the other
  one's key.
- If the credential store is unavailable, Mushroom keeps the key **in memory
  for that session only** and says so in the dialog, rather than refusing to
  work or quietly writing it to a file.
- Nothing reads it except the HTTP client, and a test walks the source tree to
  confirm no HTTP call exists outside the `ai/` module.
- Log lines are scrubbed at the writer, not at the call site, so anything
  matching `sk-…`, `Bearer …` or `api_key=` is redacted no matter which part of
  the program — or which dependency — wrote it.

## Failure messages

Every failure says what to do about it, because the fix is usually a typo:

| What happened | What Mushroom says |
|---|---|
| Nothing listening | Could not connect to `http://localhost:4000`. Check that the service is running. |
| Host does not resolve | The address `…` could not be resolved. |
| Bad certificate | Could not establish a secure connection to `…`. |
| Endpoint missing `/v1` | `…` returned 404 … LiteLLM and OpenAI usually need the endpoint to end in /v1 — try `…/v1`. |
| Key rejected | The AI service refused the key (401). Check the key in Tools → Settings. |
| Rate limited | Wait about *n* seconds and try again (read from `Retry-After`). |

## Under the hood

- One HTTP client for every provider. LiteLLM and OpenAI differ in base URL,
  whether a key is required, and the default model — configuration, not
  architecture.
- 10-second connect timeout, separate from the configurable overall timeout, so
  a wrong address fails quickly even when generation is allowed to be slow.
- **One** retry, on connect errors and 5xx only. Never on 4xx, and never on a
  timeout: retrying a timeout makes you wait the whole timeout twice.
- Cancellation aborts the in-flight request. A token cancelled before the call
  means nothing reaches the network at all — checked before the `select!`
  rather than inside it, because `select!` picks a branch at random.
- A server-sent-events parser for streamed answers, built now so milestone 05
  does not have to retrofit streaming into a one-shot request path. It handles
  frames split mid-JSON across chunks, several frames per chunk, keep-alive
  comments, and an unreadable frame in the middle.
- The whole client is tested against a **local mock server**. No test contacts a
  real provider, so the suite costs nothing, leaks nothing, and does not go red
  because somebody else had an outage.

## Upgrading

From 0.3.0: install over the top. Your settings file is migrated on first
launch — the AI section is filled with defaults and the schema version is
stamped. Your notes and search index are untouched.

## Install

- `Mushroom_0.4.0_x64-setup.exe` — per-user, no administrator rights.
- `Mushroom_0.4.0_x64_en-US.msi` — for machine-wide deployment.

Windows will warn that the publisher is unknown, because the installer is
unsigned.

## Verified by

Exercised on the built application, against real endpoints where one exists.

- **Nothing listening.** `http://localhost:4000` with no proxy running →
  "Mushroom could not connect to http://localhost:4000."
- **Unresolvable host.** `http://no-such-host.invalid/v1` → "The address
  no-such-host.invalid could not be resolved." — a different message from the
  one above, which is the point.
- **Expired certificate.** `https://expired.badssl.com/v1` → "Mushroom could
  not establish a secure connection to https://expired.badssl.com/v1."
- **Missing `/v1`, against the real OpenAI API.** `https://api.openai.com` →
  a genuine 404, and the hint naming `https://api.openai.com/v1`.
- **Invalid key, against the real OpenAI API.** A bogus key at
  `https://api.openai.com/v1` → "The AI service refused the key (401)." This
  also proves the provider preset, the TLS handshake and the bearer header.
- **Secret-leak audit, with two real keys.** Both were stored through the
  dialog and used for real requests, then every file under `%APPDATA%\Mushroom`
  was searched for them — `config.json`, the log, the database and its
  journals. Zero hits. Both were present in Credential Manager, one per
  provider, and `Clear` removed them.
- **No unsolicited requests.** The log from a cold start contains no `ai`
  request line at all until a button is pressed.
- **Validation.** An endpoint typed without a scheme shows "The endpoint must
  begin with http:// or https://" beside the field and disables OK, Apply and
  Test Connection.
- **Installed from the produced `.exe` on a clean profile**, with the data
  directory moved aside first. It started at 0.4.0, wrote a fresh `config.json`
  already stamped `"version": 2`, applied the database migration, indexed all
  five notes in 23 ms, and made no AI request at all. Settings opened showing
  the LiteLLM defaults and "No key stored." `Ctrl+F` for `GPU failure` returned
  one note with both terms marked, so milestone 03 is not regressed.
- **A real LiteLLM gateway.** Refresh listed the eleven models it serves, and
  Test Connection reported "Connected to … as gemma-4 in 381 ms".
- **OpenAI directly, with a real key.** "Connected to api.openai.com as
  gpt-4.1-mini-2025-04-14 in 2654 ms" — note that it names the dated model
  OpenAI actually used, not the `gpt-4.1-mini` alias that was asked for.
- **The request Mushroom sends**, read off a local server standing in for a
  provider:
  `{"max_tokens":1,"messages":[{"content":"ping","role":"user"}],"model":"gpt-4.1-mini","stream":false}`,
  with no `Authorization` header when no key is stored.

## Six things found by using the built application

All six passed the full test suite.

**A key could be saved under the wrong provider.** The commands that store and
clear a key read the provider from the *saved* settings. The dialog lets you
change the provider before applying, so selecting OpenAI and pasting an OpenAI
key wrote it into the LiteLLM slot — and the dialog then cheerfully reported "a
key is stored" for OpenAI, because it was reading the other slot's status. The
commands now take the provider explicitly.

**Cancel did not discard.** `Test Connection` saved the settings first, because
the client is built from saved settings. Typing a wrong endpoint, testing it,
and pressing Cancel left the wrong endpoint on disk. Testing now builds a
throwaway client from whatever is on screen.

**The useful half of each message was dropped.** The result line showed only
the error's `message` and not its `hint` — so "returned 404" appeared without
"try adding /v1", which is the only part that tells you what to do.

**Every log line since milestone 1 was written unscrubbed.** `redact()` existed,
was tested, and was never called by anything. It also had a real flaw: it
scanned for credential patterns in the order they are listed rather than by
where they appear, so a line containing `api_key=secret then sk-…` copied
`api_key=secret` out verbatim on its way to the later match. Redaction now
happens in the writer, so it cannot be forgotten, and covers output from
dependencies too.

**A key could be sent to the wrong endpoint.** `Refresh` built its request
from the *saved* settings rather than the ones on screen — the same mistake as
Test Connection, fixed in only one of the two places. Because a key is stored
the moment you press `Save key`, typing a new endpoint, saving that provider's
key and pressing `Refresh` before `Apply` sent the new key to the *previous*
endpoint. It was caught exactly that way: a gateway key arrived at a local
stub server that had no business seeing it. Both calls now take the settings
as typed, and a test pins it.

**Refresh populated a list you could not read.** The model box is an HTML
combo, and a combo filters its options by whatever is already typed. With
`gpt-4.1-mini` in the field, clicking the arrow after Refresh offered exactly
one model: `gpt-4.1-mini`. The whole purpose of the button is to find out what
a service offers, so the models now also appear in a plain list beside the
field.

**Not verified by hand:** streaming end to end — nothing consumes it until
milestone 05 — and changing the notes folder from Settings.
