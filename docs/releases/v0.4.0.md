# Mushroom v0.4.0 — DRAFT

**Released:** _pending_ · **Milestone:** 04 — AI provider

> Mushroom can now be pointed at an AI service and told to check it works.
> Nothing uses it yet — that is the next release — but the plumbing, the
> settings screen, and the key storage are all here and tested.

## What's new

- `Tools → Settings`, at last: a real settings window.
- Point Mushroom at **LiteLLM** (a proxy on your own machine or network) or at
  **OpenAI** directly. Both are OpenAI-compatible, so anything else that
  speaks the same API — Azure OpenAI through LiteLLM, Ollama, vLLM — works by
  typing its URL.
- `Test Connection` makes a real request and tells you what happened: the
  model, the round-trip time, or a specific reason it failed.
- `Refresh` lists the models your endpoint actually offers, so you do not have
  to remember model names. If the endpoint does not support listing, type it.
- Your API key goes into Windows Credential Manager. It is never written to
  `config.json`, never logged, and never sent back to the interface.
- Configure the notes folder, request timeout, context budget, and
  temperature.

## What doesn't work yet

- **No AI features use any of this yet.** The AI panel is still a frame.
  Milestone 05 is the one that asks questions.
- Streaming transport is built and tested, but nothing streams to the screen
  until 0.5.0.
- The installer is unsigned.

## Under the hood

- One HTTP client, not two. LiteLLM and OpenAI differ only in base URL, key
  requirement, and default model — so they are presets, not separate code
  paths. That is why any other OpenAI-compatible endpoint works for free.
- Error messages name the specific problem: connection refused, DNS failure,
  TLS failure, timeout, 401, 403, 404, 429, 5xx. A 404 against a URL without
  `/v1` says so, because that is the mistake everyone makes with LiteLLM.
- No AI request is ever made that you did not ask for. Mushroom does not
  contact the endpoint at startup, does not poll it, and does not retry in a
  loop — at most one retry, only on a connection error or a 5xx.
- Logs are scrubbed of anything that looks like an API key, as a second line
  of defence on top of never logging it in the first place.
- Every failure mode is covered by tests against a local mock server. No test
  contacts a real provider.

## Upgrading

From 0.3.0: settings gain an AI section, unconfigured by default. Mushroom
remains completely usable for notes and search without ever configuring it.
