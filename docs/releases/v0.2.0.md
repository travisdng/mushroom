# Mushroom v0.2.0

**Released:** 2026-09-16 · **Milestone:** 02 — Notes

> Mushroom can now hold notes. Write, save, organise into folders, preview, and
> delete — and every note is a plain Markdown file in a folder you can open with
> anything else.

## What's new

- **Create, edit, save, rename, move, and delete notes.** `Ctrl+N` makes one,
  `Ctrl+S` saves, and saving also happens on its own three seconds after you
  stop typing, when you switch notes, and when the window loses focus.
- **Notes live in `%USERPROFILE%\Mushroom\notes`** as ordinary `.md` files, in
  folders you control. The first run creates `work`, `projects`, `ideas`, and
  `personal` to start with. Nothing is locked inside the application.
- **The notebook pane** browses your folders with counts; the notes list shows
  what is in them, newest first, grouped by date.
- **Markdown preview** with headings, lists, links, code, quotes, and GFM
  tables. Edit, Preview, and Split views, on the View menu or `Ctrl+Shift+P`.
- **Deletes go to `.trash`** inside your notes folder, so they are recoverable.
  Deleting asks first, and Cancel is the default.
- **Links between notes work** — relative `.md` links and `[[wikilinks]]`.
  External links open in your browser.
- `F5` re-reads the folder, for when you have changed things outside Mushroom.

## Three things it refuses to do

These are the point of the release, more than any feature:

- **It will not reformat your Markdown.** Line endings, tabs, trailing
  whitespace, and unicode come back exactly as you wrote them. There is a test
  that writes a deliberately awkward file and asserts every byte survives.
- **It will not lose your YAML.** Mushroom owns `title`, `created`, `updated`,
  and `tags`; every other key, comment, blank line, quoting style, and the
  order you put them in is preserved. Frontmatter is edited as text rather than
  re-serialised through a YAML library, precisely because a round-trip through
  one silently reformats the whole block.
- **It will not overwrite a note that changed underneath it.** If another
  program edits a file after you opened it, saving stops and offers Keep mine
  / Load theirs / Save as copy. There is no silent-overwrite path.

## What doesn't work yet

- **No search.** Browsing only. Milestone 03, and it is next.
- **No AI.** Milestones 04 and 05.
- Mushroom does not notice external edits *live*. It checks when you save and
  refuses to clobber, and `F5` re-reads, but there is no file watcher yet —
  that is milestone 06.
- `File → Open`, `Import`, `Export`, and `Save As` are in the menus but not
  wired to a file picker yet; the backend commands exist.
- The editor is a plain text area: no syntax highlighting, no line numbers.
  Deliberate for now.
- The installer is unsigned.

## Under the hood

- A note's identity is its path relative to the notes root — no UUIDs, no
  sidecar files, nothing that makes the folder less portable.
- Saves are atomic: temp file in the same directory, fsync, then rename. A
  crash mid-save leaves the old file or the new one, never half of one.
- Every path from the UI is checked for containment before anything touches the
  disk: `..` traversal, absolute and UNC paths, Windows reserved names
  (`CON`, `NUL`, `COM1`), trailing dots and spaces, and **symlinked folders
  that point outside the notes root** are all rejected, with tests for each.
- Non-UTF-8 files are refused rather than lossily converted — opening one and
  saving it would corrupt the file you already had.
- The note list is scanned once at startup on a background thread, after the
  window is already on screen, and kept in memory. Mutations update it in
  place rather than re-walking the disk.
- The preview does not render raw HTML, and images show as `[image: alt]`
  rather than being fetched. Notes arrive by import and sync as well as by
  typing, and executing their markup would make Mushroom a way to run someone
  else's HTML.

## Numbers

Measured on a 5,000-note folder across 50 subfolders:

| Measurement | Budget | Result |
|---|---|---|
| Folder scan | < 1.5 s | **1.32 s** |
| Open one note | < 100 ms | **0.4 ms** |
| List all notes | — | 3.6 ms |
| Build the folder tree | — | 30 ms |
| Tests | — | 76 passing |

The scan first came in at 2.46 s and failed its budget. Fixing that found a
real inefficiency: the scanner was calling `fs::metadata` on every file even
though the directory walk had already fetched it. Reading the head of each file
was then split across threads. Note that these timings vary by roughly a factor
of two depending on the filesystem cache, so treat them as an order of
magnitude rather than a precise figure.

## Upgrading

From 0.1.0: install over the top. Your settings are kept, and the notes folder
is created on first launch if it does not exist.

## Install

- `Mushroom_0.2.0_x64-setup.exe` — per-user, no administrator rights.
- `Mushroom_0.2.0_x64_en-US.msi` — for machine-wide deployment.

Windows will warn that the publisher is unknown, because the installer is
unsigned.

## Verified by

Exercised against the built release binary, not the development build:

- First launch created the notes folder under `%USERPROFILE%\Mushroom` with the
  `work`, `projects`, `ideas`, and `personal` starter folders.
- `Ctrl+N`, typing the title **GPU issue**, produced `gpu-issue.md` — the
  slug the specification's own example calls for.
- Typing into the editor and pressing `Ctrl+S` wrote the body to disk with
  `created` preserved from creation time and only `updated` refreshed:

  ```
  ---
  title: GPU issue
  created: 2026-09-16T08:58:56Z
  updated: 2026-09-16T09:00:33Z
  ---
  # AI AutoQA

  The orchestrator can stop the node pool when it sees no active queue
  messages, even though transcript-processing work may still remain.
  ```

- The notebook tree showed all four folders with a live count, the notes list
  grouped the note under a `Sep 16` header, and the status bar read
  `1 note` / `Saved 4:00:33 PM`.
- `Ctrl+Shift+P` rendered the note in the preview with a proper heading rule
  and serif body text.

**Not verified:** rename, move, delete, import, and export were exercised by
integration tests against a temporary folder rather than by hand through the
interface. The conflict dialog has a test behind it but has not been seen on
screen.
