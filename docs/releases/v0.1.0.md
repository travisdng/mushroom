# Mushroom v0.1.0

**Released:** 2026-09-16 · **Milestone:** 01 — Shell

> Mushroom exists and opens. This release is the window and nothing behind it:
> menus, toolbar, panels, and status bar, all in the right style, with no
> notes, no search, and no AI yet. It is here so that everything after it has
> somewhere to live.

## What's new

- Mushroom opens as a real Windows application, at 1100x720, titled
  **Mushroom — Personal Knowledge**, with the mushroom in the title bar.
- The classic desktop shell: menu bar, toolbar, a NOTEBOOK/NOTES sidebar and
  editor pane with draggable splitters, and a status bar showing `0 notes`
  and `Ready`.
- All seven menus open by mouse and by `Alt`, with arrow-key navigation,
  right-aligned accelerators (`Ctrl+N`, `Ctrl+O`, `Ctrl+S`), separators, and
  hover-to-switch between menus. Items for features that do not exist yet are
  greyed out rather than missing — the menus are the road map.
- `View` toggles the AI panel and the status bar, and remembers the choice.
- The window remembers its position, size, and splitter positions. If it was
  last closed on a monitor you have since unplugged, it opens centred instead
  of off-screen.
- `Help → About Mushroom` and `Help → Keyboard Shortcuts`.
- The mushroom icon, drawn by hand as a pixel grid.

## What doesn't work yet

Almost everything, by design:

- **No notes.** The panels show placeholder empty states. Milestone 02.
- **No search.** `Ctrl+F` flashes "Not available yet". Milestone 03.
- **No AI.** The panel is an empty frame. Milestones 04 and 05.
- Every toolbar button except `AI` is disabled.
- The installer is unsigned, so Windows will warn that the publisher is
  unknown.

## Under the hood

- Tauri v2, Rust 1.98.1, React 19 + TypeScript (strict, with
  `noUncheckedIndexedAccess`), Vite 8.
- Native window decorations with hand-built menus in the web view. The frame
  needs correct OS behaviour — snap, double-click maximise, Alt-Tab — while
  the client area needs to look like 1997. See
  [spec 01 design](../../specs/01-app-shell/design.md).
- The error contract (`AppError` → `AppErrorDto`) and structured `tracing`
  logging with API-key redaction are in from the first release, so nothing
  later invents its own conventions.
- One vertical slice runs end to end already: the About dialog's version comes
  from a `ping` command in Rust, which is the proof that the IPC boundary
  works. Splitter positions round-trip React → service → Tauri command →
  `config.json`.
- Icons are generated from character grids by
  [`tools/make_icons.py`](../../../tools/make_icons.py) rather than stored as
  binary art: 16/24/32/48/64/128/256 PNGs plus a 7-size `.ico`. 24x24 is drawn
  separately because 16 → 24 is a 1.5x scale that would smear the pixels.

## Two bugs worth recording

Both were found by running the app rather than by reading the code.

- **Creeping window.** Geometry was saved from `outer_size()` but restored with
  `set_size()`, which sets the *inner* size. Every launch grew the window by
  exactly the decoration size — 22px wider, 56px taller — forever. Caught by
  running two full save/restore cycles instead of one.
- **Implausible geometry.** A window still being created reported a height of
  32767 (`i16::MAX`). Restoring that would leave an unusable window with no
  obvious way back, so rects outside 200–16384px are now refused on both save
  and restore.

## Where your data lives

```
%APPDATA%\Mushroom\config.json
%APPDATA%\Mushroom\logs\mushroom.log.<date>
```

Deliberately **not** `%APPDATA%\com.mushroom.app`, which is what Tauri uses by
default — data goes under the product name, where a person would look for it.

## Install

- `Mushroom_0.1.0_x64-setup.exe` (1.7 MB) — per-user, no administrator rights.
- `Mushroom_0.1.0_x64_en-US.msi` (2.4 MB) — for machine-wide deployment.

Built to
`<target>/release/bundle/{nsis,msi}/`. WebView2 is fetched by the installer if
the machine does not already have it.

Windows will warn that the publisher is unknown, because the installer is
unsigned. Choose "More info" then "Run anyway" if you trust the build, or
build it yourself from source. Do not disable SmartScreen.

## Verified by

Installed from `Mushroom_0.1.0_x64-setup.exe` and exercised as the installed
application, not the development build:

- Silent per-user install to `%LOCALAPPDATA%\Mushroom`, exit code 0, no
  administrator prompt.
- Add/Remove Programs lists `Mushroom` 0.1.0, publisher `Travis Duong`, with
  the correct icon; a `Mushroom.lnk` Start-menu shortcut is created.
- Window opens titled `Mushroom — Personal Knowledge` at 1100x720 client size.
- `Alt+H` opens the Help menu; `About Mushroom` reports **Version 0.1.0**,
  fetched from the Rust backend via `ping`.
- `Ctrl+Shift+F` toggles the AI panel, and the choice survives a restart.
- `Ctrl+N` flashes `Not available yet` in the status bar.
- The log file is written with the startup line at
  `%APPDATA%\Mushroom\logs\`.
- Window geometry round-trips across two full close/reopen cycles with no
  drift, and an off-screen saved position is replaced by centring.
- Uninstall removes the program directory, the Add/Remove entry, and the
  shortcut — **and leaves `%APPDATA%\Mushroom` untouched**, config and logs
  intact.

**Not verified:** installation on a genuinely separate Windows profile, or on
a machine without the WebView2 runtime. Creating a second user account needs
administrator rights this machine does not have, and WebView2 was already
present. The installer's `downloadBootstrapper` path is therefore untested.
