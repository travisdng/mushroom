# Mushroom v0.3.0

**Released:** _pending smoke test_ · **Milestone:** 03 — Local search

> The point of writing things down is finding them again. Mushroom now searches
> everything you have written, instantly, without touching the network.

## What's new

- **`Ctrl+F` searches your notes.** Type a word, get the notes that contain it,
  ranked, with a snippet showing the match in context and the matched words
  marked.
- **Clicking a result opens the note at the matching line**, not at the top.
  That is why the index stores heading-delimited passages rather than whole
  files.
- **Search understands** quoted `"exact phrases"`, `-exclusion`, and `prefix*`
  matching, and it stems words — searching `process` finds `processing`.
- **Scope a search to a folder** from the drop-down beside the query field.
- **The last twenty searches** are on a drop-down button next to the field.
- **`Tools → Rebuild Index`** re-reads every note, with progress in the status
  bar. The dialog states plainly that it does not modify any Markdown.
- The status bar shows `Indexing 340 / 5,000…` while working, and
  `Index out of date` if anything failed to index.

## What doesn't work yet

- **No AI.** Milestones 04 and 05. The retrieval layer this release built is
  exactly what they will use.
- **Search is keyword-based.** If you search "machine that keeps falling over"
  and your note says "node pool terminating early", it will not find it. That
  is what semantic search is for, and it is deliberately post-1.0 — see
  [spec 07](https://github.com/travisdng/mushroom).
- No date-range filter in the UI yet, though the backend supports one.
- `File → Open`, `Import`, `Export`, and `Save As` still are not wired to a
  file picker.
- The installer is unsigned.

## The index is a cache, and that is tested

Everything in `mushroom.db` is derived from your Markdown:

- **Delete the index and nothing is lost but time.** There is a test that
  indexes a folder, hashes every note, deletes the database, reopens, and
  asserts the notes are byte-identical and search still works.
- **A corrupt index does not block startup.** It is renamed to
  `mushroom.db.corrupt.<timestamp>` — kept, not deleted — and a fresh one is
  built. Also tested, by scribbling over the file.
- **An index from a newer Mushroom is refused rather than downgraded**, since
  writing an older schema over it could drop information.
- **Rebuilding never touches a note.** A test hashes every file before and
  after a full rebuild.

## Under the hood

- SQLite with FTS5, in `%APPDATA%\Mushroom\mushroom.db` — deliberately not in
  your notes folder, which stays clean and portable.
- The index stores **passages**: heading-delimited sections with their line
  range in the original Markdown. That is what makes a result open at the right
  line, and what milestone 5 will cite when the AI answers from your notes.
- FTS5 availability is probed at startup, so a bad build fails loudly then
  rather than at your first search.
- Indexing runs *after* the Markdown write succeeds, in its own transaction. An
  index failure marks the index stale; it can never fail a save.
- Startup compares modified time and size against the index and re-reads only
  what changed.
- Retrieval sits behind a `Retriever` trait with scores normalised to 0..1, so
  semantic and hybrid retrieval can be added later without touching callers.
  A `LoggingRetriever` decorator is on the real path — both useful and the
  cheap proof that the trait composes.
- Query text is never concatenated into SQL *or* into FTS5 syntax. A stray
  quote or operator degrades to a literal search rather than an error.

## Numbers

Measured on 5,000 notes across 50 folders (10,000 passages):

| Measurement | Budget | Result |
|---|---|---|
| Search | < 100 ms | **67–80 ms** |
| Startup reconciliation, nothing changed | < 2 s | **24 ms** |
| Full rebuild | — | 16.0 s |
| Index size | — | 10.1 MB |
| Tests | — | 134 passing |

The 24 ms reconciliation is the number that matters day to day: comparing
modified time and size lets startup skip reading 5,000 files entirely.

## Upgrading

From 0.2.0: install over the top. The index is built on first launch — a few
seconds for a typical folder, with progress in the status bar. Your notes are
not touched.

## Install

- `Mushroom_0.3.0_x64-setup.exe` — per-user, no administrator rights.
- `Mushroom_0.3.0_x64_en-US.msi` — for machine-wide deployment.

Windows will warn that the publisher is unknown, because the installer is
unsigned.
