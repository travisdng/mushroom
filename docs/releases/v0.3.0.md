# Mushroom v0.3.0 — DRAFT

**Released:** _pending_ · **Milestone:** 03 — Local search

> The point of writing things down is finding them again. Mushroom now
> searches everything you have written, instantly, without touching the
> network.

## What's new

- `Ctrl+F` opens search. Type a word, get the notes that contain it, ranked,
  with a snippet showing the match in context.
- Clicking a result opens the note **at the matching line**, not just at the
  top.
- Search understands quoted `"exact phrases"`, `-exclusion`, and `prefix*`
  matching, and it stems words — searching `failing` finds `failure`.
- Scope a search to a folder, or filter by when a note was last modified.
- The last twenty searches are in a drop-down on the search field.
- `Tools → Rebuild Index` rebuilds everything from your Markdown, with
  progress and a Cancel button. It states plainly that it does not modify any
  note.
- The status bar says whether the index is current.

## What doesn't work yet

- **No AI.** Milestones 04 and 05 — the retrieval layer this release built is
  what they will use.
- Search is keyword-based. If you ask for "machine that keeps falling over"
  and your note says "node pool terminating early", it will not find it. That
  is what semantic search is for, and it is deliberately post-1.0.
- External edits still are not noticed live. Milestone 06.
- The installer is unsigned.

## Under the hood

- SQLite with FTS5, stored in `%APPDATA%\Mushroom\mushroom.db` — **not** in
  your notes folder, which stays clean and portable.
- The index holds *passages*, not just notes: heading-delimited sections with
  their line ranges. That is why results open at the right line, and it is
  what makes the AI answers in 0.5.0 able to cite a specific paragraph.
- The index is a cache, not storage. Delete `mushroom.db` and it rebuilds from
  your Markdown with nothing lost. This was tested by doing exactly that and
  hashing the notes folder before and after.
- Indexing is incremental: saving a note updates only that note, after the
  file write succeeds and in a separate transaction, so an index failure can
  never cost you a save.
- Retrieval sits behind a trait with normalised scores, so semantic and hybrid
  retrieval can be added later without rewriting search.
