# Mushroom v0.5.0

**Released:** 2026-09-17 · **Milestone:** 05 — AI search

> This is the release Mushroom was for. Ask a question in your own words, get
> an answer built from your own notes, with a link to the note it came from —
> and an honest "I could not find this" when the answer is not there.

## What's new

- **Ask questions of your notes.** An `AI SEARCH` panel: a question box,
  `Ask Mushroom`, and a drop-down of your last twenty questions.
- **You see the notes before the answer.** Retrieval runs first and lists what
  it found, so there is something to read — and to judge — while the model is
  still writing.
- **Answers stream in** as they are written, with a block caret. `Stop` halts
  it; whatever arrived is kept and marked incomplete rather than thrown away.
- **Citations that go somewhere.** `[1]` in the answer is a link. Clicking it
  opens that note at the passage the excerpt came from.
- **`Sources:` shows what the model was actually given** — the excerpt text
  itself, next to each note. That is the only way to catch a model that cites a
  real note and then describes something the note does not say.
- **`Also searched`** lists the notes that were retrieved but not cited, so a
  missed answer is visible rather than silent.
- **An honest "could not find".** If retrieval finds nothing, Mushroom does not
  call the model at all — asking it to answer from nothing is asking it to
  invent. If the notes are found but do not contain the answer, the model says
  so.

## What doesn't work yet

- **Retrieval is keyword-based.** If you ask about "the machine that keeps
  falling over" and your note says "node pool terminating early", it will not
  find it. That is exactly what v1.1's semantic search is for, and it is
  deliberately after 1.0.
- `Tools → Diagnostics` is still greyed out, so the usage totals the backend
  now records have nowhere to show.
- `File → Open`, `Import`, `Export`, and `Save As` still are not wired to a
  file picker.
- The installer is unsigned.

## How an answer is built

1. **The question becomes search terms.** Leading question frames (`what did I
   write about…`) and stop words are stripped; quoted phrases are kept whole.
   No model call — rewriting every question with an LLM would double the
   latency and reach for the network before looking at your own notes.
2. **Retrieval** runs the spec-03 index and returns up to twelve passages, at
   most three from any one note.
3. **The excerpt block is built** to a token budget, dropping whole excerpts
   from the lowest-ranked end. Never truncating one: half a sentence is exactly
   what produces a confidently wrong answer.
4. **The prompt** is a file, not a string literal, so it can be read and
   diffed. It says: answer only from the excerpts, cite what you use, and say
   plainly when the answer is not there.
5. **The answer's citations are checked** against the map that was built in
   step 3.

## Grounding, and its limits

What the citation check catches:

| | |
|---|---|
| The model cites nothing | The answer renders under an `Unverified` header |
| The model cites `[9]` when eight excerpts were sent | A warning strip names it |
| The model says it could not find the answer | Reported as-is — **not** flagged as unverified, because citing nothing is correct there |

What it cannot catch: a model that writes `[1]` and then describes something
excerpt 1 does not say. Nothing mechanical can. That is why every source shows
the excerpt text it was given — so you can look.

## Upgrading

From 0.4.0: install over the top. Your settings are migrated on first launch.
Your notes and search index are untouched.

## Install

- `Mushroom_0.5.0_x64-setup.exe` — per-user, no administrator rights.
- `Mushroom_0.5.0_x64_en-US.msi` — for machine-wide deployment.

Windows will warn that the publisher is unknown, because the installer is
unsigned.

## Verified by

Against a real LiteLLM gateway running `gpt-4.1-mini`, on the built
application.

**The brief's own question.** *"What did I write about the GPU nodes shutting
down too early?"* →

> You wrote that the orchestrator can stop the node pool when it sees no active
> queue messages, even though transcript-processing work may still remain,
> which implies GPU nodes shutting down too early in that context **[3]**.

`[3]` resolved to the **GPU issue** note and opened it. The source showed the
excerpt the model was given.

**Three questions with no answer in the notes.** All three honest, none
invented:

| Question | Answer |
|---|---|
| *What did I write about my dentist appointment?* | Nothing retrieved — the model was never called |
| *How much do the GPU nodes cost per month?* | Three notes retrieved, model called: "I could not find this in your notes." |
| *Who approved the capacity planning budget and on what date?* | Three notes retrieved, model called: "I could not find this information in your notes." |

The last two are the ones that test the prompt, because the model was given
plausible-looking notes and still declined.

**Failure paths, on the running app:**

- **Stop mid-answer** — partial kept, marked incomplete, retrieved notes still
  listed, question preserved, and no error strip: stopping is not a failure.
- **A connection dropped mid-stream** — one request only, partial kept and
  marked incomplete, the failure reported.
- **The key rejected (401)** — the specific message, with the retrieved notes
  still listed and clickable.
- **AI not configured** — the plain "Answers need an AI service" panel with an
  `Open Settings` button, verified on a clean profile.
- **A cited note renamed on disk** — clicking its source says the file could
  not be read, rather than doing nothing or crashing.
- **Nothing sent until asked** — browsed folders, ran keyword searches and
  typed a question without submitting, against a server that logs every
  request. It logged none.

## Seven bugs found by using the built application

Every one passed the full test suite.

**The brief's own question retrieved nothing.** Search joins terms with `AND`,
which is right when you type two words into the search box. A question expands
to five or six terms, and no note contains all of *gpu nodes shutting down too
early* — so the flagship question returned zero passages from a corpus that
plainly held the answer. Questions now match any term, ranked by how many.

**`cargo test` deleted the developer's API key.** The credential tests store
and clear keys against the real Windows Credential Manager under the
application's own service name. Running the suite wiped whatever key was
configured; the only symptom was a 401 on the next question. It happened here,
mid-session, and took a while to attribute because nothing logged it.

**Citation markers were dead.** `react-markdown` sanitises unknown URL schemes
to an empty `href`, so the links the `[n]` markers are rewritten to arrived
looking like ordinary text — and rendered as bare `1.` and `2.`, brackets eaten
by the link syntax. No error; the milestone's headline feature simply did not
work.

**A broken stream was silently re-fetched.** A connection dying mid-answer
produces the same error as a service refusing to stream at all, so the
fallback fired and requested the whole answer again — discarding the partial
already on screen, paying twice, and hiding a real fault.

**The "not configured" state could never appear.** The endpoint always holds a
plausible default, so a first run could not be told from a deliberate local
setup, and would have opened with "could not connect to localhost:4000"
instead of the calm onboarding panel.

**Configuring AI did not un-configure the "not configured" panel.** The panel
checked once, when it mounted. So on a fresh install you would open Settings,
enter an endpoint and a key, close the dialog — and the panel would still tell
you to open Settings, until you restarted the app. Caught in the clean-profile
smoke test for this very release.

**An honest refusal was labelled "Unverified".** That header exists to warn
that an answer is not grounded. "I could not find this in your notes" cites
nothing *because there was nothing to cite* — the most trustworthy answer the
system can give. Flagging it teaches people to ignore the warning exactly where
it matters.

**Not verified by hand:** the `Refresh` model list against a provider that
changes its catalogue.
