# Mushroom v1.1.0

**Released:** 2026-09-19 · **Milestone:** 08 — AI privacy gate

> Notes contain passwords, keys and connection strings, because that is what
> people write down. Until this release, AI Search sent whatever retrieval
> selected to whatever endpoint was configured — and that included the
> credentials. This release puts a gate in front of the network.

## The short version

Two controls, and they are not equally strong:

- **Mark a note `ai: false` and it is never sent.** Not as an excerpt, not as
  a source, not in any mode. This one is complete.
- **Everything else that is sent is checked for credentials first**, and what
  Mushroom recognises is replaced with a marker. This one is best-effort and
  will miss things.

The second is a safety net. The first is the control that actually works.

## Added

**Notes can be kept out of the AI entirely.** Put `ai: false` (or
`private: true`) in a note's frontmatter and it never reaches an AI endpoint.
Mushroom reads that key and never writes it, so it survives saves untouched.
Excluded notes are otherwise completely ordinary — listed, editable, and found
by `Search Notes`. What they are kept out of is the network, not your own
machine. The note list marks them `no AI`, and the editor says so at the top.

**Whole folders too.** `Tools → Settings → Privacy → Never send` takes one
folder or pattern per line — `personal`, `work/credentials/**`,
`**/secrets.md`. A pattern that cannot be understood is shown as broken rather
than silently doing nothing. `.trash` is excluded without anyone configuring
it.

**Credential detection on everything sent.** 225 patterns — AWS, GitHub,
Slack, Google, Stripe, Azure, private-key blocks, and a rule for
`password = …` — replace what they match with `[redacted: aws-access-token]`.
The marker names the kind rather than blanking the text, so an answer to "how
does the batch runner authenticate" still makes sense.

**`Tools → Last AI Request…`** shows the exact text of the most recent
request, markers in place. Held in memory only, replaced by the next request,
never written to disk. This is the screen that lets you check rather than
trust.

**Three postures**, under `Tools → Settings → Privacy`: replace what is
recognised (the default), leave out anything that looks like a credential, or
send notes as they are. Choosing the last one asks first and names the
endpoint. Marked notes are never sent in any of them.

**A notice when the endpoint changes**, saying where note content is about to
start going and what is and is not checked.

**Diagnostics** now shows the privacy mode, how many exclusion rules are set,
and the names of any detection rules switched off — the first three questions
when something was not redacted.

## Fixed

**`log_prompts` was writing credentials to a log file.** Turning on prompt
logging to debug a bad answer wrote every retrieved excerpt — keys included —
to `logs\mushroom.log`, a plain text file that `Copy Diagnostics` does not
read but a support request might attach. It now logs the sanitised text, and
the setting says plainly that it writes note content to disk.

## What this does not do

Worth stating clearly, because a false sense of safety is worse than none:

- **Detection will miss things.** It recognises the shapes that provider keys
  take. `password: hunter2` is indistinguishable from prose at that length and
  is not caught — widening the net far enough to catch it would redact a great
  deal of ordinary writing. If a note must never leave this machine, mark it.
- **It does not protect what has already been sent.** Anything asked before
  this release went unredacted.
- **It controls what leaves Mushroom, not what happens next.** Whatever is
  sent goes to the endpoint you configured, and what that service does with it
  is between you and them.
- **Chats, tools and summaries do not exist yet** (specs 09–12). When they do,
  they go through the same gate — the test that proves it is written to be
  extended rather than replaced.

## Still not working

Unchanged from 1.0: Windows only, unsigned installer (SmartScreen will warn),
keyword retrieval only, no sync, no mobile.

## Upgrading

Settings and notes are untouched. The search index gains a column and
re-reads every note once on first launch, which takes a few seconds on a large
folder — that is deliberate, and it is what stops a note you had already
marked `ai: false` being sent on the one launch where you would most expect it
not to be.

Privacy mode starts at **replace what is recognised**. An upgrade never
selects "send as they are".
